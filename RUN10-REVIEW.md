# Run 10 independent challenge rubric

Temporary review artefact for the branch only. Remove before merge.

The candidate must survive a manual challenge against criteria fixed before final commitment:

1. Webby 2025/2026 — content, structure/navigation, visual design, functionality, interactivity, innovation and overall experience. The visitor must participate rather than merely spectate.
2. Awwwards public scoring pattern — design, usability, creativity and content; developer considerations include performance optimisation, responsive design, semantics/metadata, animation/transitions and accessibility.
3. GOV.UK design principles — user need, do less, make the hard thing simple, iterate, design for everyone and understand context.
4. WCAG 2.2 / WAI — keyboard-equivalent operation, visible focus, target usability, and suppression of non-essential motion under reduced-motion preferences.
5. GitHub Pages — static-hosting boundaries, HTTPS and no sensitive transaction handling.
6. House anti-theatre rule — no fake scale, awards, AI positioning, empty card inventory or organisational self-description as substitute for useful public experience.

Manual challenge questions:
- Is the House itself unmistakably the mobile and desktop hero?
- Can a visitor understand and operate the experience without hover?
- Is the two-page mental model obvious?
- Does interaction change meaning, not merely decoration?
- Has repetitive giant-section/card syntax been removed?
- Does the contact experience feel like part of the House rather than a generic form block?
- Would the design remain recognisably House of Carol with the wordmark removed?
- Is every empty state truthful without sounding unfinished or apologetic?
- Is the experience fast, static, recoverable and accessible?
- Does this materially beat the Chief Executive screenshots that triggered Run 10?

The branch may not merge merely because its own automated tests pass. Manual review against this fixed rubric is required.
